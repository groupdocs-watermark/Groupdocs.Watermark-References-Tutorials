# Java के साथ डायग्राम को संपादित करना और हाइपरलिंक हटाना  

डिजिटल दस्तावेज़ों का प्रबंधन अक्सर डायग्राम को संपादित करने में शामिल होता है, विशेष रूप से जब आपको सुरक्षा या दृश्य स्पष्टता के लिए हाइपरलिंक हटाने हेतु **edit diagram** फ़ाइलों को साफ़ करना पड़ता है। यह ट्यूटोरियल आपको दिखाता है कि कैसे डायग्राम फ़ाइलों को संपादित किया जाए और GroupDocs.Watermark लाइब्रेरी for Java का उपयोग करके डायग्राम शैप्स से अनचाहे हाइपरलिंक हटाए जाएँ। इस गाइड के अंत तक आपके पास एक साफ़, लिंक‑रहित डायग्राम तैयार होगा जिसे आप वितरित कर सकते हैं।  

## त्वरित उत्तर  
- **मुख्य लक्ष्य क्या है?** डायग्राम शैप्स से सभी हाइपरलिंक हटाएँ ताकि सुरक्षा और प्रस्तुति में सुधार हो सके।  
- **कौन सी लाइब्रेरी आवश्यक है?** GroupDocs.Watermark for Java, version 24.11 or newer.  
- **क्या मुझे लाइसेंस चाहिए?** परीक्षण के लिए एक फ्री ट्रायल काम करता है; उत्पादन के लिए एक व्यावसायिक लाइसेंस आवश्यक है।  
- **क्या मैं एक साथ कई फ़ाइलें प्रोसेस कर सकता हूँ?** हाँ – वही कोड लूप में रखकर बैच प्रोसेस किया जा सकता है।  
- **कौन सा Java संस्करण समर्थित है?** Java 8 या उससे ऊपर (Java 11 सिफ़ारिश किया गया)।  

## “how to edit diagram” क्या है?  
**How to edit diagram** का अर्थ है प्रोग्रामेटिक रूप से एक डायग्राम फ़ाइल खोलना, उसके आंतरिक तत्वों (जैसे शैप्स, टेक्स्ट, या हाइपरलिंक) को संशोधित करना, और परिणाम को सहेजना। GroupDocs.Watermark का उपयोग करके आप मूल ऑथरिंग टूल की आवश्यकता के बिना डायग्राम फ़ाइलें संपादित कर सकते हैं।  

## Java के लिए GroupDocs.Watermark क्यों उपयोग करें?  
GroupDocs.Watermark **30+ डायग्राम और इमेज फ़ॉर्मेट** (जैसे VSDX, SVG, और WMF) को सपोर्ट करता है और **500 MB** तक की फ़ाइलों को पूरी डॉक्यूमेंट को मेमोरी में लोड किए बिना प्रोसेस कर सकता है, जिससे कई प्रतिस्पर्धियों की तुलना में **20 % तेज़** प्रोसेसिंग स्पीड मिलती है।

## Java के लिए GroupDocs.Watermark कैसे सेटअप करें?  
`Watermarker` क्लास दस्तावेज़ लोड करने और संशोधित करने के लिए API एंट्री पॉइंट प्रदान करता है। GroupDocs.Watermark का उपयोग शुरू करने के लिए, इसके Maven कोऑर्डिनेट्स को अपने प्रोजेक्ट के `pom.xml` में जोड़ें। यह लाइब्रेरी और उसकी डिपेंडेंसीज़ को लाता है, जिससे आप Watermarker क्लास को इंस्टैंशिएट कर सकते हैं और Java कोड से सीधे डायग्राम फ़ाइलों पर काम कर सकते हैं। फिर आप लाइसेंसिंग कॉन्फ़िगर कर सकते हैं और किसी भी दस्तावेज़ को प्रोसेस करने से पहले आउटपुट विकल्प सेट कर सकते हैं।  

`pom.xml` में GroupDocs.Watermark डिपेंडेंसी जोड़ें।  

```xml
<repositories>
   <repository>
      <id>repository.groupdocs.com</id>
      <name>GroupDocs Repository</name>
      <url>https://releases.groupdocs.com/watermark/java/</url>
   </repository>
</repositories>

<dependencies>
   <dependency>
      <groupId>com.groupdocs</groupId>
      <artifactId>groupdocs-watermark</artifactId>
      <version>24.11</version>
   </dependency>
</dependencies>
```  

यदि आप Maven का उपयोग नहीं करना चाहते हैं, तो आधिकारिक रिलीज़ पेज से नवीनतम JAR डाउनलोड करें।

DiagramLoadOptions loadOptions = new DiagramLoadOptions();
Watermarker watermarker = new Watermarker("YOUR_DOCUMENT_DIRECTORY", loadOptions);

## GroupDocs.Watermark के साथ डायग्राम को संपादित करना और हाइपरलिंक हटाना कैसे करें?  
`Watermarker` क्लास दस्तावेज़ लोड करने और संशोधित करने के लिए API एंट्री पॉइंट प्रदान करता है। पहले, डायग्राम फ़ाइल को एक Watermarker इंस्टेंस में लोड करें। फिर शैप्स का संग्रह प्राप्त करें, उन शैप्स को पहचानें जिनमें हाइपरलिंक ऑब्जेक्ट्स हैं, और उन्हें रिवर्स क्रम में इटरेट करें ताकि प्रत्येक लिंक को सुरक्षित रूप से हटाया जा सके बिना संग्रह इंडेक्सिंग को प्रभावित किए। यह सुनिश्चित करता है कि सभी एम्बेडेड URLs हटाए जाएँ जबकि डायग्राम की दृश्य अखंडता बनी रहे।  

```java
DiagramLoadOptions loadOptions = new DiagramLoadOptions();
Watermarker watermarker = new Watermarker("YOUR_DOCUMENT_DIRECTORY", loadOptions);
```  

- **इस कदम का महत्व**: फ़ाइल लोड करने से आपको प्रत्येक शैप और उसकी संबंधित प्रॉपर्टीज़ तक प्रोग्रामेटिक एक्सेस मिलती है।  

## डायग्राम में शैप कंटेंट तक कैसे पहुँचें?  
`DiagramShape` ऑब्जेक्ट डायग्राम के भीतर एक व्यक्तिगत शैप को दर्शाता है, उसकी प्रॉपर्टीज़ और संलग्न मेटाडेटा को उजागर करता है। डायग्राम लोड करने के बाद, Watermarker पर `getShapes()` कॉल करके `DiagramShape` ऑब्जेक्ट्स की सूची प्राप्त करें। प्रत्येक शैप को हाइपरलिंक कलेक्शन के लिए जांचा जा सकता है, जिससे लिंक को हटाने या संशोधित करने के लिए सटीक लक्ष्यीकरण संभव होता है। यदि आगे समायोजन की आवश्यकता हो तो आप शैप टेक्स्ट, रंग, और ज्योमेट्री भी पढ़ सकते हैं।  

```java
DiagramContent content = watermarker.getContent(DiagramContent.class);
DiagramShape shape = content.getPages().get_Item(0).getShapes().get_Item(0);
```  

- **इस कदम का महत्व**: सही शैप को टार्गेट करने से आप केवल अनचाहे लिंक हटाते हैं बिना अन्य विज़ुअल एलिमेंट्स को प्रभावित किए।  

## हाइपरलिंक को सुरक्षित रूप से इटरेट और हटाना कैसे करें?  
`removeHyperlink(int index)` मेथड शैप की हाइपरलिंक कलेक्शन में निर्दिष्ट स्थिति पर हाइपरलिंक को डिलीट करता है। हाइपरलिंक सूची को अंतिम इंडेक्स से शून्य तक रिवर्स क्रम में इटरेट करें। यह रिवर्स लूप आइटम हटाने पर होने वाले इंडेक्स शिफ्ट को रोकता है, जिससे प्रत्येक हाइपरलिंक को बिना स्किप किए प्रोसेस किया जाता है। हटाने के बाद, आप शैप की स्थिति को रिफ्रेश कर सकते हैं या डायग्राम में अगले शैप पर जारी रख सकते हैं।  

```java
for (int i = shape.getHyperlinks().getCount() - 1; i >= 0; i--) {
    if (shape.getHyperlinks().get_Item(i).getAddress().contains("http://someurl.com")) {
        shape.getHyperlinks().removeAt(i);
    }
}
```  

- **इस कदम का महत्व**: रिवर्स लूप यह सुनिश्चित करता है कि सभी हाइपरलिंक बिना किसी प्रविष्टि को स्किप किए हटाए जाएँ।  

## संपादित डायग्राम को सहेजना और रिसोर्सेज़ रिलीज़ करना कैसे करें?  
`save(String path)` मेथड संशोधित दस्तावेज़ को निर्दिष्ट फ़ाइल लोकेशन पर लिखता है, सभी बदलावों को अंतिम रूप देता है। सभी हाइपरलिंक हटाने के बाद, Watermarker इंस्टेंस पर `save` मेथड को कॉल करें, मूल फ़ाइल को ओवरराइट करने से बचने के लिए नया फ़ाइलनाम प्रदान करें। फिर `close()` को कॉल करके फ़ाइल हैंडल्स रिलीज़ करें और मेमोरी मुक्त करें, जो लंबी‑चलने वाली बैच प्रोसेस के लिए आवश्यक है। यह सुनिश्चित करता है कि फ़ाइल सही ढंग से बंद हो और आगे उपयोग के लिए तैयार हो।  

```java
watermarker.save("YOUR_OUTPUT_DIRECTORY");
watermarker.close();
```  

- **इस कदम का महत्व**: रिसोर्सेज़ को सही ढंग से बंद करने से मेमोरी लीक और सर्वर पर फ़ाइल‑लॉकिंग समस्याओं से बचा जा सकता है।  

## व्यावहारिक अनुप्रयोग  
डायग्राम शैप्स से हाइपरलिंक हटाना कई वास्तविक‑दुनिया परिदृश्यों में लाभदायक हो सकता है:  

1. **Security** – ऐसे बाहरी लिंक को रोकें जो दुर्भावनापूर्ण साइटों की ओर ले जा सकते हैं।  
2. **Compliance** – साझा एसेट्स में एम्बेडेड URLs को प्रतिबंधित करने वाली कॉरपोरेट नीतियों को पूरा करें।  
3. **Clarity** – ऐसी प्रस्तुतियों को बनाएं जो साफ़ हों जहाँ लिंक ध्यान भटकाते।  

आप इस लॉजिक को बड़े ऑटोमेशन पाइपलाइन में एम्बेड कर सकते हैं, जैसे कि रात्री बैच जॉब्स जो सभी डायग्राम को इंट्रानेट पर प्रकाशित करने से पहले साफ़ कर देते हैं।  

## प्रदर्शन संबंधी विचार  

### प्रदर्शन अनुकूलन  
- फ़ाइल प्रति एकल `Watermarker` इंस्टेंस का उपयोग करके ओवरहेड कम करें।  
- रिवर्स इटरेशन को प्राथमिकता दें (जैसा दिखाया गया) ताकि महंगे लिस्ट री‑इंडेक्सिंग से बचा जा सके।  

### रिसोर्स उपयोग दिशानिर्देश  
- 200 MB से बड़े डायग्राम के लिए, हीप उपयोग की निगरानी करें और JVM `-Xmx` फ़्लैग बढ़ाने पर विचार करें।  
- VisualVM जैसे प्रोफाइलिंग टूल बड़े‑स्केल बैच रन में बॉटलनेक पहचानने में मदद कर सकते हैं।  

### Java मेमोरी मैनेजमेंट के लिए सर्वोत्तम प्रैक्टिसेज  
- ऑब्जेक्ट्स को सबसे छोटे संभव स्कोप में घोषित करें।  
- स्ट्रीम्स के साथ काम करते समय try‑with‑resources का उपयोग करें ताकि ऑटोमैटिक क्लोजर सुनिश्चित हो।  

## अक्सर पूछे जाने वाले प्रश्न  

**प्रश्न: हजारों शैप्स वाले डायग्राम को मैं कैसे हैंडल करूँ?**  
उत्तर: डायग्राम को पेज‑बाय‑पेज प्रोसेस करें और अगले पेज पर जाने से पहले प्रत्येक पेज के रिसोर्सेज़ को रिलीज़ करें ताकि मेमोरी उपयोग कम रहे।  

**प्रश्न: क्या मैं हाइपरलिंक हटाने को केवल विशिष्ट पेजों तक सीमित कर सकता हूँ?**  
उत्तर: हाँ – इच्छित पेज इंडेक्स प्राप्त करें, फिर हटाने वाले लूप को केवल उस पेज के शैप्स पर लागू करें।  

**प्रश्न: बैच प्रोसेसिंग के लिए क्या व्यावसायिक लाइसेंस अनिवार्य है?**  
उत्तर: किसी भी प्रोडक्शन‑लेवल डिप्लॉयमेंट के लिए वैध लाइसेंस आवश्यक है; फ्री ट्रायल 30 दिन और 5 डॉक्यूमेंट्स तक सीमित है।  

**प्रश्न: क्या GroupDocs.Watermark SVG डायग्राम को सपोर्ट करता है?**  
उत्तर: बिल्कुल – SVG 30+ समर्थित फ़ॉर्मेट्स में से एक है, और हाइपरलिंक को समान API कॉल्स से हटाया जा सकता है।  

**प्रश्न: यदि किसी शैप में कई हाइपरलिंक हों तो क्या होगा?**  
उत्तर: रिवर्स‑इटरेशन लूप प्रत्येक हाइपरलिंक एंट्री को व्यक्तिगत रूप से हटाता है, जिससे सभी लिंक साफ़ हो जाते हैं।
